WHERE IT LIVES (found before changing)
--------------------------------------------------------------------------
Generator:  lib/core/theme/surface_texture.dart
  - _paintCamo(canvas, t, rnd)  (the camoLobes branch of _recordTile)
  - loops `for i in 0..blobsPerTone` PER tone, placing each shard at a
    seeded-random position, then drawing it plus its 8 wrapped copies so the
    480px tile is seamless.
  - _blob(...) builds one irregular 7–11-vertex polygon whose vertices ride a
    jittered radius (random rotation + shape per shard).

Config (the knob), per skin:  lib/features/themes/domain/theme_registry.dart
  const SurfaceTexture _nightOpsTexture — this is the ONLY thing I changed.
  Density is controlled by three constructor params:
    blobsPerTone       count of shards per tone (was 72)
    minRadiusFactor    shard size floor, ×tileSize (was default 0.045)
    maxRadiusFactor    shard size ceiling, ×tileSize (was default 0.13)
  Placement is a seeded loop (seed: 7) — deterministic, not a hardcoded list.

--------------------------------------------------------------------------
THE NON-OBVIOUS PART (why "just add more shapes" backfires)
--------------------------------------------------------------------------
The tones are painted OPAQUE, in order, darkest → lightest. So the lightest
tone is laid down LAST and overwrites whatever is under it. I verified this by
rendering candidates:

  - Raising blobsPerTone alone (72 → 170) made the tile SPARSER and flatter,
    not denser: the extra top-tone shards blanketed the tile toward a uniform
    light fill, and the visible "shards" (which are really darker tones peeking
    through gaps) got covered up.

  The fix is SMALLER shards at a higher count. Each covers less, so no tone
  blankets, more tonal patches stay visible, and the empty voids break up into
  organic scatter. Confirmed by rendering the real generator output (headless
  CPU raster = the same pixels the device bakes).

CHANGE — Night Ops only
--------------------------------------------------------------------------

SHAPE COUNT
  before: 72 × 3 tones = 216 shards
  after: 120 × 3 tones = 360 shards
  (+144 shards, ~1.67×)

  Draw calls at tile BAKE (each shard × 9 wrap copies): 1944 -> 3240.
  This is a ONE-TIME cost: the tile bakes once into a cached ui.Image
  (SurfaceTexture.ensureTile), and every frame draws that single image via a
  tiled ImageShader. Per-FRAME cost is unchanged — zero extra draw calls while
  scrolling or navigating. Bake happens once per app run (or once on equip).
