## Critical Issues (verified in source)

### Empty States
- WorkoutsScreen calendar `error:` branch: `error: (_, _) => const SizedBox.shrink()` — calendar silently vanishes on DB error (workouts_screen.dart line 42)
- StrengthChart `_StrengthLineChart` error branch: `error: (_, _) => const SizedBox.shrink()` — chart silently vanishes (strength_chart.dart line 77)
- NutritionTrends `trendsAsync` error branch: `error: (_, _) => const SizedBox.shrink()` — trends silently vanish (nutrition_trends.dart line 36)
- StrengthChart exercise picker loading branch: `loading: () => const SizedBox.shrink()` — picker never appears (strength_chart.dart line 40)
- MilestoneBadges: no empty state when milestones list is empty — horizontal ListView renders nothing, 80dp SizedBox appears blank (milestone_badges.dart line 14)
- WeightChart empty state: text-only "Log your weight to see trends." — no CTA button; also fires at < 2 entries so a user with 1 entry sees the empty state (weight_chart.dart line 16)
- FoodSearchScreen "No results found." state: plain text, no icon, no barcode scan suggestion (food_search_screen.dart line 130)
- NutritionScreen: no error branch — `mealsAsync.isLoading` guard skips error path; if mealsAsync is in error state, the screen renders with empty data silently (nutrition_screen.dart lines 19-38)

### Errors
- DashboardScreen error state: `body: const Center(child: Text('Something went wrong.'))` — no retry button, no ErrorCard (dashboard_screen.dart line 50)
- WorkoutsScreen error state: `const Center(child: Text('Something went wrong.'))` — no retry button (workouts_screen.dart line 92)
- WorkoutDetailScreen error + null states: `AppBar()` with no title (workout_detail_screen.dart lines 21-30) — back relies on OS gesture only; on iOS with slide-up transition this is a dead end
- WorkoutDetailScreen inner FutureBuilder: `if (!snapshot.hasData)` with plain spinner — no error branch at all (workout_detail_screen.dart line 53-55)
- EditProfileScreen `_save()`: `findFirst()!` force-unwrap on line 76 — crash if profile deleted between screen load and save
- app_router.dart line 145: `state.extra! as FoodSearchResult` — force-unwrap crash if navigation state lost (hot-restart, deep link)
- SettingsScreen loading state: `loading: () => const SizedBox(height: 72)` — invisible placeholder (settings_screen.dart line 54)
- SettingsScreen error state: `error: (_, _) => const SizedBox.shrink()` — profile section silently disappears (settings_screen.dart line 55)

### Loading
- StrengthChart data loading: plain `CircularProgressIndicator` inside 180dp box, no shimmer (strength_chart.dart line 76)
- NutritionTrends loading: plain `CircularProgressIndicator` in 160dp box, no shimmer (nutrition_trends.dart line 35)
- WorkoutDetailScreen loading: `const Scaffold(body: Center(child: CircularProgressIndicator()))` — no AppBar shown during loading, then AppBar snaps in when data loads (workout_detail_screen.dart line 18-19)
- WorkoutDetailScreen inner FutureBuilder: second plain spinner while exercises load after AppBar is already visible — jarring two-phase load

### Tap Targets
- MealSection "Add Food" TextButton.icon: TextButton defaults to 36dp height — below 48dp requirement (meal_section.dart line 80)
- ExerciseCard "Add Set" TextButton.icon: same 36dp height issue (exercise_card.dart line 94)
- WorkoutCalendar day cells: GridView 7 columns on ~360dp = ~48dp wide but `mainAxisSpacing: 2` + `crossAxisSpacing: 2` reduce hit area; on 320dp devices cells are ~43dp — below threshold (workout_calendar.dart line 106)
- FoodEntryTile: `padding: EdgeInsets.symmetric(vertical: 6)` with no minimum height guarantee — short entries may fall below 48dp (food_entry_tile.dart line 29)
- SetRow TextField inputs: `height: 40` — below 48dp (set_row.dart lines 82, 105)

### Accessibility
- CalorieRing CustomPainter: no Semantics wrapper — screen reader sees nothing (calorie_ring.dart)
- MacroRow `_MacroBar` LinearProgressIndicator: no semantics label (macro_row.dart line 104)
- DailySummaryHeader `_MacroChip`: single-letter labels P/C/F with color only — fails color-blind users (daily_summary_header.dart line 53)
- MilestoneBadges Container: no Semantics — earned/unearned state not announced (milestone_badges.dart line 29)
- WorkoutCalendar InkWell day cells: no semanticLabel — date and workout-day status unreadable by screen reader (workout_calendar.dart line 123)
- StreakCounter `Icon(Icons.local_fire_department)`: no semanticLabel (streak_counter.dart line 20)
- WaterTracker water icon: no semanticLabel; increment/decrement IconButton.filledTonal: no tooltip (water_tracker.dart line 31)
- FoodSearchScreen Image.network: no semanticLabel on food product image (food_search_screen.dart line 148)
- ChatBubble: no Semantics role — AI vs user distinction not announced (chat_bubble.dart)
- BarcodeScannerScreen torch IconButton: no tooltip (barcode_scanner_screen.dart line 73)
- PRBanner: `Icon(Icons.emoji_events)` has no semanticLabel (pr_banner.dart line 22)
- TodayWorkoutCard icons: timer and check icons have no semanticLabel (today_workout_card.dart)

### Navigation
- WorkoutDetailScreen `AppBar()` with no title in error/null state — back arrow may not render on iOS slide-up transition (workout_detail_screen.dart line 22)
- FoodEntryTile Dismissible: no confirmation before delete — swipe instantly deletes food with no undo (food_entry_tile.dart line 22)
- BarcodeScannerScreen: after successful scan `context.go` to FoodDetail; pressing back from FoodDetail lands on NutritionScreen, not scanner — scanner is dropped from stack (barcode_scanner_screen.dart line 45)
- Onboarding has no skip option; OnboardingController state not persisted — force-quit resets to step 1

### Onboarding
- 6 steps with no persistence — force-quit at step 5 restarts from step 1
- ActivityStep subtitle is only in header text — no description per level to help user choose accurately
- No skip or "I'll do this later" option on non-critical steps

## Good Patterns (preserve these)
- DashboardScreen shimmer loading with appropriate placeholder shapes
- NutritionScreen shimmer loading
- WorkoutsScreen contextual empty state (no workouts ever vs. none on date)
- WaterTracker haptic on increment/decrement
- ShellScreen NavigationBar HapticFeedback.selectionClick() on tab switch
- WorkoutsController.completeSet: HapticFeedback.mediumImpact()
- RestTimerSheet: HapticFeedback.heavyImpact() when timer reaches 0
- AICoachScreen: friendly error messages, SocketException caught, snackbar with Dismiss action
- FoodSearchScreen: SocketException mapped to human-readable message with retry
- ProgressScreen: ErrorCard with message for milestones and weight data errors
- WorkoutLoggingScreen: discard confirmation dialog
- WorkoutDetailScreen: delete confirmation dialog
- EditProfileScreen: HapticFeedback.mediumImpact() on save
- SettingsScreen: HapticFeedback.selectionClick() on dark-mode toggle; HapticFeedback.heavyImpact() on reset
- OnboardingScreen: LinearProgressIndicator + back button shown on step > 0
- SummaryStep: isSaving disables button, shows inline spinner
- WorkoutLoggingScreen: isSaving disables Finish button, shows inline spinner
- FoodDetailScreen `_QuickButton`: SizedBox(height: 48) wrapper — correct tap target
- SetRow: SizedBox(width: 48) on complete button column — acceptable
